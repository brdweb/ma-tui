MA-TUI @VERSION@ — Omarchy / Arch Linux x86-64

Targets Music Assistant stable 2.10.5. See the accompanying README for
validation coverage and known limitations.

Install on your LOCAL Omarchy computer, not inside the SSH session:

    sha256sum --ignore-missing -c SHA256SUMS
    sudo pacman -U ./@PACKAGE@
    ma-tui --demo

This is an unsigned standalone package. Do not disable signature checking globally.
If your local package signature policy rejects it, stop and review that policy
rather than bypassing it. Dependencies are declared for pacman's normal checks.

Requires glibc >= @GLIBC@, gcc-libs, alsa-lib, ca-certificates and libsecret. PipeWire desktop
routing uses pipewire-alsa (optional package; ordinarily part of desktop audio
setup). Do not use --nodeps or --overwrite to force installation. No compiler,
Rust toolchain, Python runtime or separate Sendspin executable is needed.

RTKit is optional host support for realtime audio scheduling. If your desktop's
audio logs report unavailable realtime scheduling and you have no alternative
realtime configuration, install the distribution package separately:

    sudo pacman -S --needed rtkit

RTKit is a D-Bus-activated system service; it is not embedded in MA-TUI or the
Linux archive. MA-TUI does not install or restart audio services. Missing RTKit
alone does not establish the cause of an audio stream error.

Configure (run as your normal desktop user, NOT sudo):

    ma-tui --setup

Enter the server URL and either a built-in Music Assistant username/password or a
profile token. Login persistence requires libsecret's secret-tool and an unlocked
desktop Secret Service keyring. Passwords are not saved. Choose the local speaker
name/output and save. F2 reopens settings; ? opens all playback/player controls.
MA_TUI_TOKEN remains an optional environment override; never put it in TOML.

Local means the machine RUNNING MA-TUI. SSH does not forward audio to your laptop.
--local registers an audio endpoint; MA can send audio to it. --remote-only disables
local audio. The demo never connects or opens an audio stream.

No credentials or local configuration are shipped. Installation does not start
MA-TUI, create a service, register a player or change audio routing. Removing the
package does not remove your personal config:

    sudo pacman -R ma-tui

Read /usr/share/doc/ma-tui/README.md for keys and limitations. Enter opens collections
or a playback menu; Play now explicitly replaces the selected player's queue.
'a' appends, 'N' plays next, and 'b' opens the music browser.

Alternatively, extract the Linux archive and run ./ma-tui, or install it as your user:

    install -Dm755 ma-tui ~/.local/bin/ma-tui
    install -Dm644 ma-tui.desktop ~/.local/share/applications/ma-tui.desktop

Keep the bundled documentation and third-party license notices with the binary.
If migrating from a user installation to the Arch package, ~/.local/bin/ma-tui may
take precedence over /usr/bin/ma-tui. Check with 'command -v ma-tui' and remove or
rename only the old user executable after validating the package installation.

The release BUILDINFO.json records the executable build origin and compiler.
Arch makepkg wraps that executable; it is not an Arch source rebuild or an
official repository/AUR package.
Historical live local and remote playback on Music Assistant 2.10.2 was confirmed
on the development laptop. That evidence is not live 2.10.5 validation. Other
hardware, prolonged playback, server restart during streaming, codec/format
transitions and multi-room sync are not covered by that historical evidence.
